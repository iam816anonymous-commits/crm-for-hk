# Data Privacy, Security, Consent, & Retention Architecture

## Executive Summary
This document defines the privacy, security, consent management, encryption, and data lifecycle retention policies for the Rental Property CRM / Communication Intelligence System. Given that the platform processes Personally Identifiable Information (PII), WhatsApp chat messages, call metadata, voice recordings, and AI transcripts, strict adherence to global privacy regulations (GDPR, CCPA, TCPA) is mandatory.

---

## 1. Data Protection & Encryption Architecture

```
+-----------------------------------------------------------------------------------+
|                        ENCRYPTION & DATA PROTECTION STACK                         |
+-----------------------------------------------------------------------------------+
|                                                                                   |
|  [ In-Transit ]     HTTPS (TLS 1.3) / WSS Signature Verification (HMAC-SHA256)   |
|                                                                                   |
|  [ In-Rest ]        PostgreSQL Transparent Data Encryption (AES-256)             |
|                     S3 Server-Side Encryption (SSE-KMS / AES-256)                 |
|                                                                                   |
|  [ Application ]    PII Field-Level Encryption (Deterministic AES-256-GCM)       |
|                     E.164 Phone Number Hashing for Lookups (HMAC-SHA256)         |
|                                                                                   |
|  [ Access ]         Role-Based Access Control (RBAC) + Row-Level Security (RLS)   |
+-----------------------------------------------------------------------------------+
```

### 1.1 Phone Number & PII Protection
* **Format Normalization**: All incoming phone numbers are parsed and validated into **E.164 standard format** (e.g., `+14155552671`).
* **Field-Level Encryption (FLE)**: Direct phone numbers, emails, customer full names, and tax IDs are encrypted at the application layer using AES-256-GCM before writing to PostgreSQL.
* **Deterministic Hashing for Lookup**: To enable indexed database queries (`WHERE phone_number_hash = ?`) without storing plaintext phone numbers, a secure HMAC-SHA256 hash of the normalized phone number is stored alongside the encrypted payload.
* **Masking in UI**: Phone numbers displayed in the agent CRM frontend are masked by default (e.g., `+1 (415) ***-2671`). Full unmasking requires explicit agent permission and triggers an audit log entry.

### 1.2 WhatsApp Messages & Media Storage
* **In-Transit Security**: All webhook payloads from Meta Cloud API are encrypted over TLS 1.3 and validated using `X-Hub-Signature-256`.
* **Media Blob Security**: Inbound WhatsApp images, documents, and voice notes (`.opus`) are immediately downloaded from Meta's temporary storage and stored in private S3-compatible object storage with **Server-Side Encryption (SSE-KMS)** enabled.
* **Public Access Blocked**: Direct public URL access to S3 media buckets is strictly disabled. Media access is granted exclusively via short-lived (15-minute expiration) pre-signed S3 URLs generated for authenticated CRM agents.

### 1.3 Call Metadata, Recordings & Transcripts
* **Audio Storage**: Call recordings captured via Cloud Telephony (Twilio/Exotel) or uploaded by agents are stored in encrypted S3 buckets (`AES-256`).
* **Transcript Protection**: Audio transcripts generated by speech-to-text models (Whisper) are stored in PostgreSQL with field-level encryption for sensitive conversation segments.
* **PII Redaction in Transcripts**: Prior to feeding call transcripts into LLMs for requirement extraction, automated Named Entity Recognition (NER) filters mask sensitive numerical tokens (credit card numbers, national identity numbers, passwords).

## 2. Consent Management Framework

Processing communication data legally requires explicit consent mechanisms tailored to the communication channel.

```
+-----------------------------------------------------------------------------------+
|                           CONSENT MANAGEMENT WORKFLOW                             |
+-----------------------------------------------------------------------------------+
|                                                                                   |
|  [ WhatsApp Inbound ]  --->  Automatic Opt-in Confirmation Message                |
|                              "Reply STOP to unsubscribe at any time."             |
|                                                                                   |
|  [ Voice / Phone Call ] ---> Automated IVR Announcement                           |
|                              "This call is recorded for quality & training."     |
|                              (Continued call = Affirmative Consent)               |
|                                                                                   |
|  [ Web Form Lead ]     ---> Checkbox: "I agree to receive WhatsApp messages."     |
+-----------------------------------------------------------------------------------+
```

### 2.1 WhatsApp Opt-In / Opt-Out Mechanisms
* **Opt-In Requirement**: Outbound WhatsApp template messages can only be sent to customers who have provided affirmative consent (e.g., website contact form checkbox, inbound inquiry initiation, or physical visit sign-up).
* **Automated Opt-Out (Unsubscribe)**: The CRM system monitors incoming messages for keywords such as `STOP`, `UNSUBSCRIBE`, `CANCEL`, or `QUIT`.
* **Instant Blacklisting**: When an opt-out keyword is detected, the system immediately updates `customers.status = 'INACTIVE'` and blocks all automated outbound messaging to that number.

### 2.2 Call Recording Consent Compliance
* **Two-Party / One-Party Consent**: To comply with strict telephone recording laws (such as US State Two-Party Consent laws and European GDPR regulations):
  * **Inbound Telephony**: Automated IVR plays a mandatory prompt before routing to an agent: *"Thank you for calling [Business]. Please note that this call may be recorded for quality and compliance purposes."* Continuing the call constitutes legal consent.
  * **Outbound Telephony**: Cloud Telephony dialer plays an audio tone or automated prompt informing both agent and recipient that recording is active.

## 3. Data Retention & Lifecycle Schedules

Data must not be retained indefinitely. The CRM enforces automated retention schedules aligned with property business needs and legal data minimization rules.

| Data Classification | Storage Location | Active Retention | Retention Post-Inactivity | Purge Method |
| :--- | :--- | :--- | :--- | :--- |
| **Raw Webhook Payloads** | `raw_source_records` | 30 Days | 30 Days | Automatic hard delete via SQL Partition Drop |
| **Voice Recordings (.wav/.mp3/.opus)** | S3 Private Bucket | 90 Days | 90 Days | S3 Lifecycle Rules transition to expiration |
| **Call Transcripts & Summaries** | PostgreSQL `calls` | 1 Year | 2 Years | Automated anonymization / text scrub |
| **WhatsApp Text Messages** | PostgreSQL `messages` | 2 Years | 3 Years | Soft delete -> Hard purge |
| **Customer Profile & Requirements** | PostgreSQL `customers` | Active Relationship | 5 Years (Tax/Lease audit) | Pseudonymization / Anonymization |
| **Audit Log Entries** | PostgreSQL `audit_logs` | 7 Years | 7 Years | Immutable cold storage backup |

## 4. Right to be Forgotten (GDPR / CCPA Deletion & Anonymization)

When a customer or owner submits a Data Erasure Request ("Right to be Forgotten"):

```
+-----------------------------------------------------------------------------------+
|                        DATA ERASURE / ANONYMIZATION WORKFLOW                      |
+-----------------------------------------------------------------------------------+
|                                                                                   |
|  [ Erasure Request Received ]                                                     |
|              |                                                                    |
|              v                                                                    |
|  [ Verify Active Leases / Financial Obligations ]                                 |
|              |                                                                    |
|       +------+------+                                                             |
|       |             |                                                             |
|       v (No Active  v (Active Financial Contract Exists)                          |
|         Lease)      |                                                             |
|       |             v                                                             |
|       |     [ Anonymize Non-Financial PII ]                                       |
|       |     (Retain lease records under tax compliance legal hold)                |
|       |                                                                           |
|       v                                                                           |
|  [ Purge Personal Data ]                                                          |
|   - Overwrite phone_number -> 'ANONYMIZED_' + UUID                               |
|   - Overwrite first_name, last_name -> 'DELETED_USER'                             |
|   - Delete S3 Audio Recordings & Media Files                                      |
|   - Delete raw_source_records associated with wa_id                               |
|              |                                                                    |
|              v                                                                    |
|  [ Emit Audit Log Entry ] ('CUSTOMER_ANONYMIZED_GDPR')                            |
+-----------------------------------------------------------------------------------+
```

### 4.1 Step-by-Step Deletion Protocol
1. **Verification**: Confirm customer identity and verify whether open leases or unpaid balance transactions exist in `transactions`.
2. **Media Hard Purge**: Issue API call to S3 bucket to hard-delete all associated audio recordings, voice notes, and uploaded PDF documents.
3. **Database Anonymization**:
   * Replace `first_name` and `last_name` with `ANONYMIZED_USER`.
   * Replace `phone_number` and `whatsapp_id` with a cryptographically generated string `ANONYMIZED_<UUID>`.
   * Nullify `email`, `address`, and `metadata`.
4. **Preservation of Statistical Aggregate Data**: Keep property visit timestamps and lead stage history for business analytics, but ensure all linkages to personal identity are severed.
5. **Audit Logging**: Write a permanent, non-reversible audit log entry: `ACTION: DATA_ERASURE_FULFILLED, PERFORMED_BY: SYSTEM_PRIVACY_SERVICE`.

## 5. Security & Privacy Feature Matrix

### SUPPORTED
* Application-level AES-256-GCM encryption for phone numbers and sensitive PII.
* HMAC-SHA256 verification for Meta WhatsApp webhooks.
* Short-lived S3 pre-signed URLs (15-minute max lifetime) for audio recordings and media files.
* Automated opt-out keyword processing (`STOP`, `UNSUBSCRIBE`).
* IVR call recording consent announcements via Cloud Telephony.
* Automated S3 lifecycle rules for raw audio purge after 90 days.
* Role-Based Access Control (RBAC) restricting PII viewing to authorized agents.

### POSSIBLE WITH LIMITATIONS
* **Historical Data Retention for Legal Compliance**: Active lease holders cannot have transaction records deleted until statutory tax/accounting retention periods expire (e.g., 7 years). Data is pseudonymized instead.
* **On-Premise Audio Storage**: Cloud Telephony recordings temporarily buffer on provider servers before transfer to private S3. Requires provider SOC2 compliance verification.

### NOT SUPPORTED / SHOULD NOT BE USED
* **Storing Plaintext Phone Numbers in Log Files**: Disallowed; all application logging must sanitize phone numbers.
* **Storing Unencrypted Recording Files in Public S3 Buckets**: Prohibited; causes severe privacy leakage.
* **Processing WhatsApp Outbound Broadcasts without User Opt-In**: Violates Meta TOS and privacy laws.
* **Silent Unannounced Call Recording**: Illegal in two-party consent jurisdictions.

---

## 6. Recommended Security Architecture Summary

1. **Deploy Zero-Trust Database Encryption**: Combine PostgreSQL Transparent Data Encryption with application-side field-level encryption for phone numbers.
2. **Automate Consent & Compliance Triggers**: Embed opt-out keyword parsers directly into the WhatsApp ingestion webhook worker.
3. **Strict S3 Media Access Control**: Block public access on media S3 buckets and stream recordings through authorized pre-signed URLs.
4. **Implement Automated Privacy Jobs**: Schedule daily cron jobs to execute data retention purges and fulfill pending GDPR anonymization requests.
